# Google BigQuery Connector — заметка по аутентификации (OAuth)

Дата анализа: 2026-08-31

## Коротко: OAuth ЕСТЬ, серверный — Service Account JSON key (как GCP Connector)

Коннектор подключается к проекту Google Cloud через **Service Account JSON
key**: ключ скачивается из GCP Console и целиком вставляется в панель
Imperal. Коннектор сам подписывает JWT и обменивает его на access token —
браузер не нужен.

## Как устроено подключение

В панели Imperal вставляется **полный JSON-ключ Service Account**
(client_email, private_key, project_id). Аккаунту нужны роли для BigQuery
(минимум BigQuery Data Viewer + BigQuery Job User; для создания датасетов/
таблиц — BigQuery Data Editor).

## Что автоматизировано, а что — руками

| Этап | Как делается |
|---|---|
| Создание Service Account | **РУКАМИ** — GCP Console → IAM & Admin → Service Accounts |
| Выдача ролей BigQuery | **РУКАМИ** — IAM |
| Создание JSON-ключа | **РУКАМИ** — Keys → Add key → JSON |
| Обмен JWT на токен, обновление | **АВТОМАТИЧЕСКИ** |

## Почему не браузерный OAuth

BigQuery — инфраструктурный сервис: коннектор работает от имени сервиса 24/7
(запросы, датасеты, запланированные запросы), а не от имени человека с его
сессией. Service Account — рекомендованный Google способ.

## Следствие для тестирования

Полный тест (датасеты, таблицы, SQL-запросы, scheduled queries) требует
JSON-ключ реального проекта с включённым BigQuery API.

## Важно (инфраструктурное)

Это одно из приложений, которое платформа на момент проверки отклоняла при
деплое как «not one of your apps» — фиксы платформенных контрактов
(id/title, summary) запушены в репозиторий, но вопрос владения/видимости
приложения на платформе остаётся открытым.
